# Project page — "Co-Design Rankings Do Not Survive Realization"

Static site (no build step, no framework): `index.html` + `site.css` + `viewer.js`, Three.js vendored
in `vendor/`, one GLB per morphology and design space in `models/`, figures in `figs/`, gallery
thumbnails in `figs/thumbs/`. Classic academic layout (centred title / authors / buttons, the 3D
viewer as the teaser, one-line TL;DR with the abstract folded away, four key numbers, two figures,
an 18-card gallery where every card shows the morphology as the abstract simulator sees it → as a fabricable
robot with both scores, the realization spec list, the full table collapsed, BibTeX).
The 3D viewer replays the *training-time trajectories* (`genesis_rl/videos/*_traj.npz`, written by
`record_icos.py`) through MuJoCo forward kinematics; nothing is re-simulated in the browser.

## Preview locally

```bash
cd website && python3 -m http.server 8000     # then open http://localhost:8000
```
(Opening `index.html` from the file system does not work — ES modules and `fetch` need http.)

## Deploy

Any static host works. GitHub Pages: push this folder to a public repo (or the `docs/` folder of one),
Settings → Pages → deploy from branch. Total size ≈ 40 MB, dominated by `models/` (36 GLBs, 0.4–1.9 MB
each). Nothing is loaded from third-party hosts except the Google Fonts stylesheet.

   `export_terrain.py` only needs re-running if the terrain parameters change.

## Which CAD the viewer shows

The policies were trained on the **hw7** hardware model. The fabricable-space GLBs replay those
trajectories on the **current leg design (v50)** — `mjcf_pack/mjcf/{R}_mjx_v50vis.xml`, generated by
`tools/make_v50_visuals.py` from the hw7 files: identical leg frames, joint axes and link lengths
(J2 at 89 mm, J3 at 209 mm, foot at 329 mm; the v50 leg frame sits 6 mm outside the MJCF one, which is
where hw7's `conn12` geom already sat), only the visual meshes are swapped for
`mjcf_pack/mesh/v50_{mount,conn1,conn2,foot,motor,body}.stl` (decimated exports of the "ICOS Leg v50"
design). Mount orientation about the face normal follows the CAD gates for the quadruped and vertex-0
alignment elsewhere. `python build_models.py --variant hw7` rebuilds the trained model's own meshes
instead. The abstract-space GLBs are drawn as the proxies that simulator computes with (`make_abs_visuals.py`;
`--abs-variant sci` restores the science files' own meshes, which are an early hardware iteration's partA/partB).
When the CAD moves on: re-export the six STLs (mm, same frames), re-run `make_v50_visuals.py`
(adjust `OFF`, `J2`, `J3` there if the joint layout changes), then `build_models.py --spaces fabricable`.

## Files

| path | role |
|---|---|
| `tools/build_site.py` | renders `index.html` from `data/results.json`; **authors, links, venue and BibTeX are the constants at the top** — edit there and re-run |
| `tools/render_thumbs.py` + `tools/thumb.html` | rest-pose renders of every GLB (headless Chromium + the vendored three.js) → `figs/thumbs/<id>_{fab,abs}.webp`; `pip install playwright pillow && playwright install chromium` once, then `python render_thumbs.py` |
| `tools/mjcf_to_glb.py` | MJCF → GLB: visual geoms, Open3D decimation to 1500 tris/mesh, body nodes, one glTF animation per clip (25 Hz), Z-up → Y-up root |
| `tools/build_models.py` | discovers clips per morphology/space and writes every GLB + `models/index.json` (`--variant`, `--spaces`, `--only`; keeps index entries it does not rebuild) |
| `tools/make_v50_visuals.py` | hw7 MJCF → `{R}_mjx_v50vis.xml` with the v50 visual meshes (see below) |
| `tools/make_abs_visuals.py` | science MJCF → `{R}_mjx_absvis.xml`: the abstract skeleton drawn as capsules + joint spheres (the science files dress it in an early hardware iteration's partA/partB meshes) |
| `tools/export_terrain.py` | the seed-0 rubble heightfield (exact) and an illustrative stepping-stone field |
| `tools/build_preview.py` | single-file preview with a few morphologies embedded (for sharing without hosting) |
| `viewer.js` | Three.js viewer: OrbitControls, follow camera, terrain meshes, path trail, readouts; gallery cards load into it |
| `data/results.json` | the paper's 18×5 table + ranks + symmetry scores (from `paper_iros2026/`) |
| `figs/fig_slope.png`, `figs/fig_rho_a.png`, `figs/fig_rho_b.png` | Fig. 1 and the two panels of Fig. 2 (`fig_rho.png` is the uncut original) |

After new GLBs: `python render_thumbs.py` (≈2 min for 36) then `python build_site.py`.
